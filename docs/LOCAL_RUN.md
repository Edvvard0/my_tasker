# Локальный запуск на ПК (Windows): сервер + приложение

Инструкция для проверки приложения целиком на своём компьютере: настоящий бэкенд, настоящая база, вход по паролю и коду, синхронизация. Серверный проход проверен в облачной среде (миграции, `/health/ready`, создание владельца); запуск Flutter на Windows и работа приложения с этим сервером на вашем ПК не проверялись — ошибки сборки или входа присылайте с текстом.

Короткий путь: **сервер** (шаги 1–4) → **приложение** (шаги 5–6) → **проверка** (шаг 7).

## Что нужно установить

| Что | Зачем | Как проверить |
|---|---|---|
| Git | клонировать репозиторий | `git --version` |
| Docker Desktop | поднять PostgreSQL одной командой | `docker --version` |
| uv (менеджер Python) | запустить бэкенд на Python 3.13 | `uv --version` (установка: `winget install astral-sh.uv`) |
| Flutter 3.47.5 (stable) | собрать приложение | `flutter --version` |
| Visual Studio 2022 с нагрузкой «Разработка классических приложений на C++» **и компонентом ATL** | сборка под Windows (нужна плагину `flutter_secure_storage`) | `flutter doctor` — пункт Windows зелёный |

Без Docker можно поставить PostgreSQL 17 обычным установщиком — дальше везде подставьте свой пароль и порт.

Репозиторий: `git clone <адрес репозитория> my_tasker` и `git checkout claude/intelligent-planck-1i9ery` (в этой ветке вся работа; после слияния — основная ветка).

## 1. База данных

PowerShell, любая папка. Пароль придумайте свой и **только из букв и цифр** (он вставляется в адрес подключения как есть):

```powershell
docker run -d --name tasker-pg -e POSTGRES_PASSWORD=ВашПарольБукваЦифры -p 5432:5432 postgres:17-alpine
# если Docker Hub отвечает 429: mirror.gcr.io/library/postgres:17-alpine
docker exec tasker-pg psql -U postgres -c "create database tasker"
```

Остановить и запустить позже: `docker stop tasker-pg` / `docker start tasker-pg`. Данные сохраняются в контейнере; снести всё: `docker rm -f tasker-pg`.

## 2. Настройка сервера

Откройте PowerShell в папке `my_tasker\backend` и задайте переменные окружения (действуют только в этом окне):

```powershell
cd my_tasker\backend
uv sync --locked

$env:APP_ENV = "dev"
$env:DATABASE_URL = "postgresql://postgres:ВашПарольБукваЦифры@localhost:5432/tasker"
$env:APP_SECRET_KEY = (uv run python -c "import secrets; print(secrets.token_hex(32))")
$env:FILES_DIR = "$PWD\files-data"          # вложения (этап «Учёба»)
New-Item -ItemType Directory -Force $env:FILES_DIR | Out-Null
```

**Запомните `APP_SECRET_KEY`.** Он шифрует секрет кода из приложения-аутентификатора. Если при следующем запуске задать другой, вход скажет `owner_secret_unreadable` — тогда выполните `uv run python -m tasker.cli user reset`. Чтобы не терять ключ, сохраните его в менеджер паролей и в следующий раз задавайте тем же значением: `$env:APP_SECRET_KEY = "..."`.

Необязательно, для ИИ-чата (нужен свой ключ polza.ai; **никогда не записывайте его в файлы репозитория**):

```powershell
$env:POLZA_API_KEY = "ваш ключ"
```

Без ключа всё остальное работает, а чат ответит ошибкой сервера.

## 3. Миграции и владелец

```powershell
uv run python -m tasker.db_migrations      # создаёт таблицы (должно дойти до «0013»)
uv run python -m tasker.cli user create    # пароль 12–256 символов, вводится дважды
```

Команда `user create` **один раз** напечатает секрет TOTP (строка `otpauth://...secret=XXXX`). Добавьте его в приложение-аутентификатор на телефоне (Google Authenticator, Aegis, 2FAS, Microsoft Authenticator): «добавить вручную» → вставьте значение `secret`, тип «по времени», 6 цифр, 30 секунд. Потеряли — `uv run python -m tasker.cli user reset` создаст новый пароль и новый секрет.

Публичной регистрации нет: владелец один, создаётся только этой командой.

## 4. Запуск сервера

В том же окне PowerShell:

```powershell
uv run uvicorn tasker.main:create_app --factory --no-access-log
```

Проверка в другом окне: `curl http://localhost:8000/health/ready` → `{"status":"ok"}`. Окно с сервером оставьте открытым.

Второе окно — **воркер** (чистка корзины раз в час, очередь Telegram-алертов этапа «Серверы»). Для проверки приложения он не обязателен. Если запускаете, в новом окне задайте те же `APP_ENV`, `DATABASE_URL`, `APP_SECRET_KEY`, `FILES_DIR` и выполните `uv run python -m tasker.worker`.

## 5. Сборка и запуск приложения

Новое окно PowerShell:

```powershell
cd my_tasker\app
flutter config --enable-windows-desktop
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter run -d windows
```

Первая сборка занимает несколько минут (скачивается SQLCipher). Запускайте именно `flutter run` (режим debug): только в нём приложение разрешает **`http://localhost`** без сертификата. В `--release` и в боевой сборке адрес обязан быть `https` с закреплённым сертификатом.

В окне терминала: `r` — горячая перезагрузка, `R` — перезапуск, `q` — выход.

## 6. Первый вход

1. Приложение откроется на экране входа и скажет, что сервер не настроен; перейдите к настройке сервера (кнопка на экране входа, либо «Настройки → Сервер»).
2. Адрес сервера: `http://localhost:8000` → «Сохранить адрес» → «Проверить соединение». Должно появиться «Соединение установлено» (для localhost сертификат не нужен).
3. Вернитесь на экран входа: пароль владельца, **код из приложения-аутентификатора** (6 цифр, меняется каждые 30 секунд), имя устройства (например «ПК»). Вход.
4. Должен открыться экран «Сегодня».

Если вход пишет «Неверный пароль или код» — проверьте пароль и что время на ПК и на телефоне точное (код зависит от времени).

## 7. Что проверить

Разделы в боковой панели. Для каждого — минимальный сценарий:

- **Календарь и задачи:** создать событие и задачу, повторяющееся событие, подзадачу, быстрый ввод («встреча завтра в 15:00 p1»), виды день/неделя/месяц.
- **Сегодня:** карточки на день; после настройки сна и чек-ина — блоки «Утренний план» и «Вечерний чек-ин».
- **Работа:** создать заказчика и проект, доработку, платёж с распределением, посмотреть «Мне должны», запустить и остановить таймер. «Серверы» (Пульс) — вкладки открываются, но проверки не идут без движка Gatus (на ПК он не запускается).
- **Финансы:** счёт, операции, перевод между счетами, цель с формулой «Есть», аналитика; PIN-замок раздела и «скрыть суммы». Случай из Excel: «Есть» 329 600 → 454 600 с кредиткой → «Цель достигнута +54 600».
- **Банки** (внутри «Финансы»): импорт выписки — нужен файл CSV/XLSX/PDF (синтетические образцы лежат в `backend/tests/data/banks/`). Слушатель уведомлений работает только на Android.
- **Учёба:** семестр, предметы, звонки и пары, особый день («по четвергам подготовка к олимпиаде»), отметка посещаемости, долг по предмету, вложение файлом.
- **Сон:** запись «лёг/встал», история, утренний план, вечерний чек-ин с переносом задач.
- **ИИ-чат:** нужен `POLZA_API_KEY`; агенты «Календарь», «Работа», «Финансы» (перед запуском с финансами спросит согласие), «Учёба», «Сон». Карточка «создать задачу» — одобрить/отклонить.
- **Синхронизация, устройства, корзина:** «Настройки → Устройства», «Синхронизация», «Корзина»; удалить запись → она в корзине → восстановить.

### Проверка синхронизации между двумя устройствами

Для настоящей проверки «телефон ↔ ПК» нужен сервер, доступный по `https` (приложение принимает `http` только для localhost и только в debug). Для этого поднимите Docker-стенд из `deploy/README.md` (Caddy выдаёт сертификат на IP) и на каждом устройстве закрепите его корневой сертификат. Без телефона приложение можно проверить целиком на одном ПК — синхронизация с сервером при этом тоже работает (экран «Синхронизация» покажет состояние и журнал).

## Чего на ПК не будет

- Слушатель банковских уведомлений, камера для фото заданий, уведомление-таймер с кнопкой «Стоп» (на Windows вместо трея — плашка в приложении), локальные напоминания Android — только на телефоне.
- Локальная ИИ-модель: работает на Android (Galaxy A55); на ПК — только облачный чат.
- Мониторинг серверов с реальными проверками и Telegram: нужен Gatus и Docker-стенд (`deploy/README.md`).

## Вариант «как на сервере»: весь стек в Docker

Полный боевой стек (Caddy с HTTPS по IP, закрепление сертификата, api, worker, Postgres): см. `deploy/README.md`, раздел «Запуск локально». Приложению нужно будет указать `https://127.0.0.1` и закрепить корневой сертификат Caddy (кнопка «Получить сертификат сервера» → сверить отпечаток). Для обычной проверки экранов проще путь выше.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `flutter doctor`: Visual Studio не найден | поставить нагрузку C++ для настольных приложений **и ATL** |
| сборка падает на `flutter_secure_storage_windows` / `atlbase.h` | не установлен компонент ATL |
| `curl /health/ready` → 503 | база не запущена (`docker start tasker-pg`) или миграции не накатаны |
| сервер не стартует: ошибка про `APP_SECRET_KEY` | ключ короче 32 символов или не задан |
| вход: `owner_secret_unreadable` | `APP_SECRET_KEY` отличается от того, с которым создавали владельца — `uv run python -m tasker.cli user reset` |
| вход: блокировка после неудач | `uv run python -m tasker.cli user unlock` |
| приложение не принимает `http://localhost:8000` | запущено не через `flutter run` (debug) |
| чат: ошибка сервера | не задан `POLZA_API_KEY` или нет доступа к polza.ai |
| хочется начать с нуля | `docker rm -f tasker-pg`, шаги 1–3 заново; в приложении на экране «Синхронизация» есть «Полная пересинхронизация»; чтобы стереть и локальные данные, выйдите из учётной записи и удалите папку данных приложения (путь покажет `flutter run` в логе при ошибках БД, обычно внутри `%APPDATA%`/`%LOCALAPPDATA%`) |

Ошибки присылайте с текстом из терминала (`flutter run` и окна сервера): правки кода делает облачная сессия.

## Готовые файлы из GitHub Actions

> Сборка на раннерах GitHub ещё ни разу не запускалась (workflow `.github/workflows/build.yml` не проверен до первого пуша): если запуск упал, пришлите лог.

**Где взять.** GitHub → вкладка **Actions** → workflow **Build** → последний успешный запуск → внизу раздел **Artifacts**. Запустить сборку вручную: **Run workflow** (кнопка справа). Сборка идёт и при пуше в рабочую ветку, если менялась папка `app/`, и при теге `v*`. Артефакты хранятся 14 дней.

- **`my-tasker-windows`** — zip с папкой Release (скачивается как zip в zip). Установка не нужна: распакуйте в любую папку целиком (не копируйте один `.exe`) и запустите `my_tasker.exe`.
- **`my-tasker-android-apk`** — файл APK. Скачайте на телефон (или передайте с ПК), откройте и разрешите установку из неизвестных источников для браузера/файлового менеджера (Настройки → Приложения → особый доступ → Установка неизвестных приложений). Если секреты подписи (`ANDROID_KEYSTORE_*`) в репозитории не заданы, файл называется `app-release-debug-signed.apk` — он подписан debug-ключом и годится только для проверки; обновление поверх такой версии возможно только с тем же ключом.

**Важно про адрес сервера.** Release-сборки (и APK, и exe) принимают только `https` с закреплённым сертификатом сервера; `http://localhost` работает лишь в debug-сборке `flutter run`. Поэтому:

- проверка с локальным сервером без HTTPS — только через `flutter run` (раздел 5);
- APK и exe из Actions используйте с сервером за Caddy (`deploy/README.md`): в приложении получите сертификат сервера и сверьте отпечаток.
