# Выжимка этапа 10. ИИ-чат офлайн (локальная модель на телефоне)

> Для субагентов. Читать вместо больших документов; первоисточники — только по ссылкам.
> Порядок изменён по решению заказчика (2026-10-02): **логику пишем сейчас**, параллельно другим этапам; **замеры на Galaxy A55 — в конце**, в фазе сборки.

## Что уже есть

- Этап 3 (`docs/specs/stage3_ai_chat.md`, `docs/briefs/stage-3.md`): облачный чат через сервер, таблицы бесед/сообщений/предложений, у беседы поле `mode = cloud | local` (сервер пока работает только с `cloud`), карточка предложения задачи с одобрением по неизменяемому `entity_id`, профили агентов, конструктор контекста с флагом «чувствительные данные — не в облако».
- Клиент чата этапа 3 пишется сейчас в `app/lib/features/ai_chat/` — **его файлы не трогать**; интеграция с UI чата — отдельным небольшим шагом после его завершения.

## Решения оркестратора

1. **Где работает:** только Android (Galaxy A55: Exynos 1480, 8 ГБ ОЗУ, **только CPU** — GPU Xclipse в LiteRT-LM даёт мусор). На Windows офлайн-модели нет: режим `local` там недоступен (понятное сообщение).
2. **Рантайм за интерфейсом** `LocalLlmEngine` (загрузка модели, генерация потоком токенов, отмена, освобождение памяти, сведения о модели). Основная реализация — **flutter_gemma (LiteRT-LM) + Gemma 4 E2B-it**; запасная — **llama.cpp (llamadart) + Qwen GGUF Q4** — только заготовка адаптера. Окончательный выбор — по замерам в конце. Платформенная склейка тонкая, вся логика тестируется на поддельном движке.
3. **Менеджер моделей:** каталог разрешённых моделей (id, URL, размер, SHA-256, лицензия) в коде; загрузка **только по Wi-Fi** по умолчанию, с продолжением после обрыва, проверка SHA-256, хранение в каталоге приложения, удаление, показ занятого места; проверка свободного места и ОЗУ перед загрузкой и запуском.
4. **Маршрутизация:** беседа создаётся с режимом `cloud` или `local`. Нет сети и модель скачана → предложить продолжить локально. Облачный запрос без сети не теряется: сообщение пользователя сохраняется, кнопка «отправить в облако, когда появится сеть».
5. **Контекст офлайн:** лёгкий пресет (задачи на сегодня и неделю, расписание на 3 дня, просроченное) с жёстким бюджетом токенов (≈ 1500); **чувствительные пресеты разрешены** — данные не покидают телефон.
6. **Создание задачи офлайн:** модель отвечает JSON по схеме `create_task` (те же поля, что в этапе 3). Строгий разбор и валидация; при невалидном JSON — один повтор с подсказкой, затем обычный текст без карточки. Карточка и одобрение — **как в облаке**: предложение пишет клиент с `entity_id` = UUIDv7 клиента, одобрение создаёт ровно одну задачу.
7. **Синхронизация локальных бесед:** сообщения ассистента, сообщения инструмента и предложения для бесед `mode = local` пишет **клиент** (в облачных беседах — по-прежнему сервер). Если сервер сейчас отклоняет такие строки — **минимальное изменение бэкенда**: разрешить клиентские строки `role = assistant|tool` и предложения только для бесед `local`; облачные правила не меняются; обновить контракт этапа 3 (раздел о сообщениях и предложениях) и тесты.
8. **Расход:** у локальных сообщений стоимость 0, лимит polza.ai не применяется.
9. **Экран замеров (для фазы сборки):** в настройках ИИ — «Тест локальной модели»: прогон 20 фиксированных русских фраз (из них 10 на создание задачи), метрики: время до первого токена, токенов в секунду, пиковая память, доля валидного JSON, температура/троттлинг если доступно; результат можно скопировать текстом. Этот экран заказчик запустит на A55 в конце.

## Объём

- `app/lib/core/local_llm/`: интерфейс движка, адаптер flutter_gemma, заготовка адаптера llama.cpp, менеджер моделей, промпт-шаблон Gemma (чат-формат), разбор JSON-ответа, бюджет токенов, сервис локального чата (поток, отмена, запись сообщений и предложений).
- `app/lib/features/local_ai/`: экран моделей (скачать, удалить, место), экран замеров, переключатель режима (виджет, который чат этапа 3 подключит позже).
- При необходимости — малое изменение бэкенда по п. 7.

## Тесты (облегчённый процесс, `04` §2.4)

Поддельный движок (детерминированный поток токенов, обрыв, мусорный JSON, медленный первый токен): поток и отмена, разбор JSON (≥ 30 случаев: валидный, частичный, с текстом вокруг, неверные поля, пустой), одна задача на одобрение, менеджер моделей (докачка, неверный SHA-256, нет места, нет Wi-Fi), маршрутизация офлайн/онлайн, синхронизация локальной беседы на второе устройство через поддельный сервер. Golden — только экран моделей.
