Контракт — `docs/specs/stage5_finance.md`, экраны — `docs/02_DESIGN_SYSTEM.md`. Банки (этап 6) отложены решением заказчика. ## Ограничение, общее для срезов: клиента «Работы» (этап 4) в приложении ещё нет

Локальных таблиц Работы нет, поэтому:
- «Контрагент» долга — только текст (`counterparty`); выбор человека из `people` (`person_id`) недоступен, поле остаётся `null`.
- В «Есть» цели слагаемое «ожидаемые поступления из Работы» считается по пустым данным Работы (0). Экран честно пишет об этом: «Раздел «Работа» ещё не подключён — ожидаемые поступления сейчас считаются как 0». Формула с таким слагаемым **сохраняется и синхронизируется как есть** (на других устройствах и сервере она посчитается полностью). Когда появится клиент Работы, достаточно подставить данные в `goalProgress`.
- Связь «платёж Работы → доход» (`work_payment`) не делаем.

## Срез 5b: долги и погашения

- Таблицы `debts`, `debt_repayments` уже есть (spec 1.5, 1.6, 6.1). Добавить: клиентскую валидацию (зеркало серверной, тест паритета с `backend/src/tasker/finance/schema.py`, как у счетов), методы репозитория (CRUD долгов, погашения, восстановление из корзины, расчёт состояний через `debtState`/`debtsSummary`), провайдеры.
- Экраны (design doc, раздел про долги и взаиморасчёты; без дебиторки Работы): «Долги» — две вкладки/секции «Мне должны» и «Я должен», итог по каждой, список с остатком, статусом (открыт / частично / закрыт) и просрочкой; карточка долга с историей погашений; редактор долга (направление, контрагент текстом, сумма, дата, срок, комментарий); добавление погашения (сумма, дата, заметка; частичное и полное «закрыть остаток»); вход в экран из раздела «Финансы».
- **Движение денег.** Погашение и выдача могут быть привязаны к реальной операции счёта: при погашении предложить «создать операцию на счёт» (выбор счёта) — тогда клиент создаёт операцию (`income` для «мне вернули», `expense` для «я вернул») с `debt_id` = этот долг, подтверждённую, и погашение с `transaction_id` = её id; расхождение — ошибка валидации `repayment_transaction_mismatch` как в спеке. «Списать без движения денег» («простил», «зачли») — погашение без операции. При создании самого долга можно по желанию создать операцию выдачи/получения займа (`debt_id`). Операции с `debt_id` не входят в «доход/расход» месяца (spec 5.1) — это уже учтено в домене, тестами подтвердить в ленте.
- Удаление долга уносит погашения каскадом сервера (одна операция delete долга); операции с `debt_id` остаются (spec 2). Корзина показывает долги и погашения.
- Состояния каждого экрана: пусто / загрузка / данные / ошибка / офлайн. Напоминание о сроке уведомлением — **не** делаем.
- Тесты: паритет валидации, репозиторий (погашения, статусы, просрочка по московской дате, переплата), связка «погашение + операция» (балансы счёта меняются, «доход» месяца — нет), widget каждого экрана, golden «Долги» (телефон+десктоп), синхронизация (круг: создал офлайн → второе устройство; удаление долга каскадом).

## Срез 5c: цели и аналитика

- **Цели** (spec 1.7, 6.2, 6.3; brief этапа 5 п. 7): список целей с прогрессом (полоса обрезается на 100 %, процент усечением до одной цифры, `progress_bp`), «Есть», «Не хватает» (отрицательное = «цель достигнута, +X»), срок; карточка цели с таблицей разбора слагаемых (`terms`); редактор цели с **конструктором формулы «Есть»**: слагаемые `accounts` (выбор счетов), `all_accounts`, `debts_to_me`, `my_debts`, `receivables`, знак +/−; при добавлении `my_debts` знак по умолчанию «−»; предупреждение о пересечении `all_accounts` и `accounts`; формула по умолчанию у новой цели — как в спеке 6.2 (воспроизводит Excel заказчика); клиентская валидация формулы (3.1: 1–30 слагаемых, ключи, размер ≤ 8 КБ) + паритет с сервером; архив цели. Слагаемое `receivables` — см. ограничение выше.
- **Аналитика** (spec 5): экран с выбором периода; доход / расход / итог по месяцам (`monthlyTotals`, пропуски месяцев заполняет клиент); расходы и доходы по категориям с подкатегориями (`categoryBreakdown`, группа «без категории»); топ мерчантов; остатки по счетам; динамика общего баланса (`balanceDynamics` на концы месяцев + сегодня). Графики — **оттенки серого с одним синим акцентом** (design doc); использовать то, что уже есть в `pubspec.yaml` (если графической библиотеки нет — собственные `CustomPainter`, новых зависимостей не добавлять без крайней необходимости; если добавляешь — назови в отчёте с обоснованием). Пустые данные: «Нет операций за этот период» (design doc ~стр. 993). Чёрные/серые цвета — из токенов темы, не хардкодом.
- Глоссарий метрик (spec 5.1) показывается подсказкой на экране аналитики («что такое доход месяца», «общий баланс»).
- Тесты: формула цели на Excel-случае через UI-слой (значения 329 600 / 454 600 / «+54 600»), конструктор (знаки, пересечение, лимиты), аналитика на границе месяца по Москве, widget каждого экрана, golden «Цели» и «Аналитика» (телефон+десктоп).

## Срез 5d: приватность и ИИ

- **Замок раздела «Финансы»**: PIN (4–6 цифр, хранится как хеш с солью в защищённом хранилище, которое уже используется приложением — найти, как хранится ключ БД/токены) и биометрия, если устройство поддерживает (подключить стандартный пакет только если его нет; назвать в отчёте). Блокировка при выходе из раздела / сворачивании приложения (настройка: сразу / через 1 мин / через 5 мин); защита от подбора (пауза после 5 неверных попыток). Экран ввода PIN, настройка замка в разделе «Финансы» (включить, сменить PIN, отключить с подтверждением PIN). Замок — **только клиент**, сервер не участвует.
- **Режим «скрыть суммы»**: переключатель в разделе «Финансы» (и быстрая кнопка-«глаз» на главном экране); суммы показываются как `•••• ₽` на всех экранах Финансов (счета, лента, долги, цели, аналитика, виджеты «Сегодня», если там есть суммы финансов); состояние запоминается локально.
- **Провайдер контекста ИИ на клиенте** для агента «Финансы» (этап 3: `lib/features/ai_chat`, смотри как устроены провайдеры контекста Календаря и Задач и конструктор контекста; серверные инструменты уже есть в `backend/src/tasker/finance/tools.py`): балансы по счетам, доходы/расходы за период по категориям, прогресс целей, долги — с превью перед отправкой и с учётом режима «скрыть суммы» (скрытые суммы в ИИ не отправляются без явного подтверждения пользователя в превью). Тесты по образцу тестов контекста других модулей.
- Тесты: PIN (хеш, неверные попытки, пауза, смена, отключение), блокировка при сворачивании (таймеры на fake clock), режим «скрыть суммы» на каждом экране Финансов (widget-тест: ни одной цифры суммы), контекст ИИ, golden экрана PIN.

## Как работать (всем срезам)

- Структура и стиль — как в 5a (`lib/features/finance/{application,data,domain,presentation}`), образцы — календарь и задачи. Деньги — только целые копейки, `lib/core/money`.
- Критерии готовности: `dart format` чисто, `flutter analyze` 0, `flutter test` зелёный (кроме двух известных Windows-падений в `test/app_test.dart`), покрытие ≥ 90 % (`dart tool/check_coverage.dart --min=90`), секретов нет, прошлые тесты не сломаны. Новые golden — только для новых файлов (`--update-goldens <файл>`), все PNG посмотреть глазами; существующие эталоны не обновлять.
- Не коммитить и не пушить: коммитит оркестратор после проверки.
