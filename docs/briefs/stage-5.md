# Выжимка этапа 5. Финансы

> Для субагентов. Читать вместо больших документов; первоисточники — только по ссылкам.

## Что уже есть

- Этап 1: синхронизация с реестром таблиц (`docs/specs/stage1_sync_and_auth.md`).
- Этап 3: реестр инструментов ИИ на сервере (`docs/specs/stage3_ai_chat.md`; встроенные агенты берут инструменты из кода).
- Этап 4: «Работа» (`docs/specs/stage4_work.md`) — проекты, платежи, **дебиторка по заказчикам** (остатки по проектам, без лидов и отменённых). Она нужна Финансам как «ожидаемые поступления».

## Решения оркестратора и заказчика

1. **Валюта — только RUB**, деньги — целые копейки, никаких округлений, кроме явно описанных делений (вниз).
2. **Счета:** наличные, дебетовая карта, кредитная карта, накопительный счёт, вклад, другое. Банк (текст), последние 4 цифры карты (понадобятся банкам в этапе 6), начальный остаток с датой, «учитывать в общем балансе», архив.
   - **Кредитка — это баланс** (ответ заказчика): у неё, как у любого счёта, баланс = начальный + операции; положительный баланс — доступные деньги. Отдельного «долга по кредитке» в v1 нет. Кредитный лимит — справочное поле.
3. **Операции:** расход, доход, перевод (между своими счетами, две стороны одной записью или парой — решить в контракте так, чтобы перевод **никогда** не считался доходом или расходом), дата-время, категория, контрагент/мерчант (текст), комментарий, **источник** (вручную / уведомление / выписка / платёж по проекту), **внешний id или хеш для дедупликации** (заготовка под этап 6), **статус** (подтверждена / черновик / требует проверки — черновики не входят в балансы). Связь с платежом «Работы» — необязательная ссылка; если пользователь отмечает «деньги по проекту пришли на карту», создаётся доход со ссылкой на платёж (без двойного учёта в аналитике: доход считается один раз).
4. **Точки сверки баланса** (`BalanceCheckpoint`): фактический баланс счёта на момент. Расчётный баланс = последняя точка + операции после неё; расхождение с предыдущим расчётом показывается как «корректировка». Это фундамент для сверки с банком в этапе 6.
5. **Категории:** двухуровневые (родитель → подкатегория), тип расход/доход, предустановленный набор на русском (≈ 15 расходов, 5 доходов), иконка.
6. **Долги:** мне должны / я должен, контрагент (person из `people` или текст), сумма, дата, срок, погашения частями (`DebtRepayment`, необязательно со ссылкой на операцию), статус вычисляется (открыт / частично / закрыт).
7. **Цели с настраиваемой формулой «Есть»** (ответ заказчика: «сам буду настраивать»). У цели: название, целевая сумма, срок, и **список слагаемых** с знаком +/−: конкретные счета, «все счета в общем балансе», «долги мне (открытые остатки)», «мои долги», «ожидаемые поступления из Работы (дебиторка, все заказчики или выбранные)». «Не хватает» = цель − Есть (может быть отрицательным → «цель достигнута, +X»).
   - **Обязательный вектор — случай из Excel заказчика:** счета 54 000 + 174 000 + 8 000, долги мне 7 500 + 2 600 + 3 000, ожидаемые от Ромы 20 000 + 60 500 → Есть 329 600; плюс кредитка 125 000 как счёт → Есть 454 600; цель 400 000 → «Не хватает −54 600» (цель достигнута с запасом 54 600). Формула по умолчанию у новой цели воспроизводит этот расчёт.
8. **Аналитика:** доходы/расходы по месяцам (Europe/Moscow = UTC+3), по категориям (с подкатегориями), топ мерчантов, остатки по счетам, динамика общего баланса. **Глоссарий метрик** в контракте: «доход месяца» = подтверждённые доходы без переводов; «расход месяца» = подтверждённые расходы без переводов; «общий баланс» = сумма счетов с флагом.
9. **Приватность (клиент):** замок раздела PIN/биометрия и режим «скрыть суммы» — только клиент, сервер не участвует.
10. **ИИ:** инструменты чтения для агента «Финансы»: балансы по счетам, доходы/расходы за период по категориям, прогресс целей, долги. Через реестр этапа 3.

Первоисточник деталей: `docs/01_ARCHITECTURE_PLAN.md` §5.4 и §6.3 (где не противоречит решениям выше; ZenMoney и бюджеты — **не** в этом этапе).

## Объём бэкенда

Контракт `docs/specs/stage5_finance.md` (таблицы, валидация, правила расчёта балансов, переводов, сверок, долгов, целей, аналитики с примерами, глоссарий, инструменты ИИ) → миграция → валидация → эталонные расчёты на Python → общие векторы `shared-test-vectors/finance/*.json` (≥ 70 случаев, включая случай Excel) → инструменты ИИ → тесты.

## Объём клиента

Счета и общий баланс, лента операций с фильтрами, ввод операции (быстрый — сумма, категория, счёт), перевод, сверка баланса, категории, долги с погашениями, цели с конструктором формулы «Есть» и прогрессом, аналитика (месяцы, категории — графики оттенками серого с синим акцентом), замок раздела и «скрыть суммы», провайдер контекста ИИ.

## Тесты (облегчённый процесс, `04` §2.4)

Высокий риск: балансы, переводы (никогда не доход/расход), сверки и корректировки, долги с частичными погашениями, формула цели (Excel-случай), аналитика по месяцам на границе суток по Москве, черновики не входят в итоги — всё на общих векторах. Golden — только счета/баланс, операция, цель.
