# Выжимка этапа 5, клиент. Срез 5a: счета, категории, операции, переводы, сверка

> Для субагентов. Решения ниже окончательные. Контракт и расчёты — `docs/specs/stage5_finance.md`, общий бриф этапа — `docs/briefs/stage-5.md`, экраны — `docs/02_DESIGN_SYSTEM.md` (раздел «Финансы», поле суммы ~стр. 673). Банки (этап 6) **отложены**: пока всё вводится вручную.

## Решение заказчика (2026-10-02)

Сначала логика «сам завожу счета и сам добавляю все транзакции». Уведомления, выписки и сверка с банком автоматически — позже (этап 6). Срез 5a делает именно это. Остаток этапа 5 (долги, цели, аналитика, замок раздела, провайдер ИИ) — срезы 5b–5d после приёмки 5a.

## Что входит в 5a

1. **Данные и синхронизация.** Drift-таблицы и регистрация в реестре синхронизации **всех семи таблиц** этапа 5 (`accounts`, `categories`, `transactions`, `balance_checkpoints`, `debts`, `debt_repayments`, `goals`) одним шагом миграции схемы — чтобы 5b–5d не требовали новой миграции. UI в 5a — только для первых четырёх. Образец: `lib/core/db/calendar_tables.dart`, `lib/features/calendar/data/calendar_sync_specs.dart`, `lib/features/tasks/data/task_sync_specs.dart`, `lib/core/sync/registered_tables.dart`. Порядок регистрации — как в спеке (раздел 1). Валидация значений на клиенте — зеркало серверной (3.1 спеки), проверяется тестом паритета как у календаря (`test/features/calendar/validation_parity_test.dart`).
2. **Домен на Dart** (чистые функции на «JSON-строках», побайтно те же результаты, что у `backend/src/tasker/finance/reference.py`): `effect`, `balance_at`, общий баланс, `adjustments`, `dedup_key`, id предустановленных категорий (`uuid5`). Векторы `shared-test-vectors/finance/` (`balances.json`, `adjustments.json`, `categories.json`, `category_ids.json`, `integrity.json` и др.) — **все случаи этих файлов проходят на Dart**; смотри `shared-test-vectors/README.md` (домен `finance`) и образец `test/core/calendar/calendar_vectors_test.dart`. Деньги — `lib/core/money/money.dart`, никаких double.
3. **Предустановленные категории** засеваются клиентом после первой полной синхронизации по правилам спеки 3.2 (детерминированные id, не воскрешать удалённые).
4. **Экраны** (заменить заглушку `lib/features/finance/finance_screen.dart`; адаптив телефон/десктоп как у остальных модулей):
   - «Финансы»: общий баланс, список счетов с балансами, быстрые действия; левая панель счетов на десктопе.
   - «Счёт»: баланс, операции счёта, действие «Сверить баланс».
   - Редактор счёта (создать/править/архивировать; предупреждение при архивации счёта с ненулевым балансом).
   - Лента операций с фильтрами (счёт, категория, вид, период, поиск по сумме и мерчанту), липкий месячный итог.
   - Редактор операции: сегмент «Расход / Доход / Перевод», поле суммы с автоформатом и чипами, счёт, категория, дата-время, мерчант, комментарий; для перевода — «откуда/куда». Предупреждение, если операция задним числом (раньше последней точки сверки, спека 4.2).
   - Категории: список, создание, правка, удаление; двухуровневые.
   - Сверка баланса: ввод фактического остатка → точка `source = manual`, показ корректировки (спека 4.4).
   - Состояния каждого экрана: пусто, загрузка, данные, ошибка, офлайн — как у экранов календаря.
   - Кнопка «+» в разделе «Финансы» по умолчанию создаёт операцию (`lib/features/shell/quick_create_sheet.dart`).
5. **Корзина и синхронизация.** Удаление — мягкое по правилам этапа 1; каскады спеки раздела 2 (удаление счёта уносит операции обеих сторон перевода и точки сверки). Операции и счета в корзине появляются на экране корзины (`lib/features/trash`). Правило видимости из раздела 2 соблюдается во всех запросах.
6. Все операции, созданные в 5a: `source = manual`, `status = confirmed`.

## Не входит в 5a

Долги и погашения (UI), цели и формула «Есть», аналитика и графики, замок раздела и «скрыть суммы», провайдер контекста ИИ, связь с платежами Работы (`work_payment`), банки, импорт, дедупликация (поля `external_id`/`dedup_hash` в таблице есть и синхронизируются, но в UI не используются).

## Как работать

- Сначала прочитать: `CLAUDE.md`, этот файл, `docs/specs/stage5_finance.md` (разделы 0–4 и 10), образцы модулей `lib/features/tasks` и `lib/features/calendar` (структура `application/data/domain/presentation`), `docs/02_DESIGN_SYSTEM.md` (токены, финансовые экраны).
- Структура: `lib/features/finance/{application,data,domain,presentation}`; общая доменная логика, нужная и другим модулям, — в `lib/core/finance/` по образцу `lib/core/calendar_time`, `lib/core/recurrence`.
- Тесты по `docs/04_DECISIONS_AND_ROADMAP.md` §2.4: векторы Dart (все случаи), паритет валидации, репозиторий, круг синхронизации (создал офлайн → ушло → пришло на второе устройство, как `test/features/tasks/sync_roundtrip_test.dart`), widget-тесты каждого экрана (данные/пусто; ошибка и офлайн где нужно), golden — «Финансы со счетами», «Редактор операции» на телефоне и десктопе (эталоны на Linux не обновлять на Windows: см. `test/goldens/README.md`).
- Критерии готовности: `dart format` чистый, `flutter analyze` без замечаний, `flutter test` зелёный (golden-расхождения только платформенные — сообщить отдельно), покрытие ≥ 90 % (`dart tool/check_coverage.dart --min=90`), секретов нет. Регрессия: тесты прошлых этапов остаются зелёными.
- Не коммитить и не пушить: коммитит оркестратор после проверки.
