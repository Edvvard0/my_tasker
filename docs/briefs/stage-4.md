# Выжимка этапа 4. Работа

> Для субагентов. Читать вместо больших документов; первоисточники — только по ссылкам.

## Что уже есть

- Этап 1: синхронизация с реестром таблиц (`docs/specs/stage1_sync_and_auth.md`).
- Этап 2: таблицы `projects` (название, цвет, архив) и `people` (имя, архив) — заготовки. **Этап 4 расширяет эти же таблицы новыми необязательными колонками**, id не меняются (`docs/specs/stage2_calendar_tasks.md` §2.3, §4.3). У задач уже есть `project_id`, `person_id`.
- Этап 3: ИИ-чат с реестром инструментов и провайдеров контекста на сервере (`docs/specs/stage3_ai_chat.md`) — этап 4 добавляет инструменты «Работы».

## Решения оркестратора

1. **Как сейчас ведёт пользователь (Excel «Эдвард_Рома»):** проект (базовая сумма) → доработки (у каждой своя сумма и статус «в работе / закрыт»); оплаты разнесены по месяцам. Заказчик подтвердил: **месячные колонки — это факт** полученных денег. Данные пользователь внесёт сам, импорт Excel не делаем.
2. **Сущности** (первоисточник: `docs/01_ARCHITECTURE_PLAN.md` §5.3, §6.5):
   - `projects` (+ заказчик → person, партнёр → person или пусто, статус: лид / в работе / пауза / завершён / отменён, тип оплаты: фикс / почасовой, базовая сумма, ставка в час, **моя доля в %** (по умолчанию 100), через кого идут деньги по умолчанию: напрямую / через партнёра, даты, описание, ссылки);
   - `people` (+ роль: заказчик / партнёр / другое, контакт — свободный текст);
   - `change_requests` (доработки): проект, название, сумма, статус (в работе / закрыта / отменена), дата закрытия, оценка часов, заметка;
   - `payments` (факт поступления): дата, сумма, от кого, **кто получил деньги** (я / партнёр), комментарий;
   - `payment_allocations`: платёж → проект или доработка, сумма (один платёж может закрывать несколько доработок, доработка — оплачиваться частями; сумма распределений не больше суммы платежа);
   - `partner_settlements`: партнёр, направление (я → партнёру / партнёр → мне), сумма, дата, комментарий (фактические переводы между мной и Ромой);
   - `time_entries`: проект, доработка (необязательно), задача (необязательно), начало, конец (пусто — таймер идёт), оплачиваемое, заметка, источник (таймер / вручную).
   - **Графика оплат (план) в v1 нет**: «сколько ещё должны» = остатки по проектам и доработкам.
3. **Расчёты** — только целые копейки, RUB, одинаково на сервере и клиенте, **общие векторы** `shared-test-vectors/work/*.json`:
   - сумма проекта = базовая + доработки (кроме отменённых); получено = сумма распределений; доля оплаты = получено / сумма; остаток = сумма − получено;
   - моя часть = округление(сумма × доля %), правило округления — одно, зафиксировать в контракте (банковское или вниз — выбрать и описать);
   - **взаиморасчёт с партнёром** по каждому распределению проекта с партнёром и моей долей s: если деньги получил партнёр — партнёр должен мне s·сумма; если получил я — я должен партнёру (1−s)·сумма; переводы `partner_settlements` уменьшают долг. Итог: «Рома должен мне X» или «я должен Роме X»;
   - доход в час по проекту и общий: показываем оба варианта — **по факту** (моя часть полученного / часы) и **по начисленному** (моя часть закрытых доработок + базовой суммы завершённых проектов / часы); часы — только оплачиваемые записи;
   - помесячная разбивка полученного (как колонки Excel) — по дате платежа в Europe/Moscow.
4. **Трекер времени:** один идущий таймер на устройстве; если после синхронизации идут два (запущены офлайн на разных устройствах) — показать предупреждение и дать остановить любой. Таймер переживает закрытие приложения и перезагрузку (хранится начало). Android — постоянное уведомление с таймером и кнопкой «Стоп»; Windows — трей. Платформенная часть тонкая, за интерфейсом.
5. **Архив:** проекты со статусом «завершён»/«отменён» можно архивировать; архив — отдельный список, данные не удаляются.
6. **ИИ:** серверные инструменты чтения для агента «Работа»: проекты со статусами и остатками, долг партнёра, часы и доход в час за период. Через реестр этапа 3.

## Дизайн

`docs/02_DESIGN_SYSTEM.md` §5.4 «Таблицы и списки Работы: как превратить Excel в интерфейс» и макеты «Работа» в §6. Монохромный стиль (`docs/references/ref2_workout_app.jpg`), крупные цифры, синий — только акцент.

## Объём бэкенда

Контракт `docs/specs/stage4_work.md` (таблицы, валидация, правила расчётов с примерами, инструменты ИИ) → миграция (расширение `projects`/`people` + новые таблицы) → валидация → эталонные расчёты на Python для векторов → инструменты ИИ → тесты.

## Объём клиента

Список проектов (активные / архив), карточка проекта в стиле «Excel-интерфейса» (доработки, оплаты, остаток, моя часть, часы, доход в час), ввод платежа с распределением, экран «Взаиморасчёты с Ромой», трекер времени (старт/стоп из проекта и из задачи, уведомление и трей), сводка «кто сколько должен», провайдер контекста ИИ для чата «Работа».

## Тесты (облегчённый процесс, `04` §2.4)

Высокий риск: все денежные расчёты на общих векторах (≥ 60 случаев: частичные оплаты, один платёж на несколько доработок, отменённые доработки, доля 0/50/100 %, округление, переводы партнёру, деньги через партнёра и напрямую), трекер (перезапуск, два таймера после синхронизации). Golden — только список проектов, карточка проекта, взаиморасчёты.
