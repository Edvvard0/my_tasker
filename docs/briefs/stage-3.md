# Выжимка этапа 3. ИИ-чат (онлайн)

> Для субагентов. Читать вместо больших документов; первоисточники — только по ссылкам ниже.

## Что уже есть

- **Этап 1** (`docs/specs/stage1_sync_and_auth.md`): вход, устройства, общий движок синхронизации с реестром таблиц, корзина, SSE `/events`, `server_epoch`. Новые таблицы регистрируются в реестре и синхронизируются автоматически.
- **Этап 2** (`docs/specs/stage2_calendar_tasks.md`): календари, события, задачи (5 статусов, P1–P5), подзадачи, теги, заготовки проектов и людей. Все таблицы лежат в PostgreSQL на сервере.
- Бэкенд: `backend/src/tasker/` (FastAPI, async SQLAlchemy, Alembic, structlog, worker). Клиент: `app/` (Flutter).

## Решения оркестратора

1. **Провайдер:** polza.ai, OpenAI-совместимый API (чат с SSE-стримингом, вызов инструментов, `/models`). Адрес — env `POLZA_BASE_URL`, ключ — env `POLZA_API_KEY`. **Ключ только на сервере**: не попадает в ответы, логи, ошибки и клиент. Точные id моделей не зашиваем: каталог берём из `/models`, быстрый выбор настраивает пользователь.
2. **Поток чата:** клиент собирает контекст локально (конструктор контекста с превью) и отправляет запрос на сервер → сервер проксирует в polza.ai со стримингом и ретранслирует дельты клиенту по SSE → по завершении сервер сохраняет ответ ассистента как синхронизируемую строку (серверная запись, приходит на все устройства обычным pull). Отмена на клиенте отменяет запрос к polza.ai.
3. **Инструменты агента** выполняются **на сервере** над синхронизированными данными (в БД сервера уже есть задачи и события):
   - читающие: задачи (фильтры по статусу, приоритету, датам), события за период;
   - `create_task` **не создаёт задачу сразу**: сервер записывает предложение (ToolProposal, статус «ожидает»). Клиент показывает карточку, пользователь правит и одобряет или отклоняет. Задачу создаёт **клиент** локально (обычная синхронизация), предложение получает статус и id задачи. Одно одобрение = ровно одна задача (идемпотентно).
   - Реестр инструментов и провайдеров контекста расширяемый: этапы 4–8 добавляют свои (проекты, финансы, учёба, сон).
4. **Агенты по разделам:** 6 предустановленных (общий, календарь и задачи, работа, финансы, учёба, сон), системный промт редактируется, история версий, кнопка «Сбросить».
5. **Чувствительные данные:** у пресета контекста флаг «не отправлять в облако». Такой пресет нельзя использовать в облачном чате; он для локальной модели (этап 10).
6. **Расход:** токены и стоимость в рублях на каждое сообщение (из `usage` ответа и цен из каталога моделей; деньги — целые копейки). Месячный лимит в `user_settings` (`ai.monthly_limit_kopecks`), сервер проверяет его до отправки и возвращает понятную ошибку.
7. **Тесты без денег:** в CI нет реальных вызовов polza.ai. Только поддельный upstream-сервер на записанных ответах (стриминг, вызов инструментов, ошибки 4xx/5xx, обрыв посреди стрима).

## Тесты (по `04` §2.4, облегчённый процесс)

Высокий риск: ключ не утекает (ответы, логи, ошибки), стриминг с обрывом и отменой, ровно одна задача на одобрение, лимит блокирует запрос, корректная стоимость в копейках. Golden — только экран чата и карточка задачи.
