# Выжимка этапа 7. Учёба

> Для субагентов. Требования заказчика от 2026-10-02 — главное; первоисточники 01/02 — только где выжимка молчит.

## Требования заказчика (дословно по смыслу)

1. Считать пропущенные пары; пары можно отмечать **отменёнными** — отменённые не пропуски.
2. **По четвергам обычных пар нет: 3 пары — подготовка к олимпиаде.**
3. Настраивать расписание: добавлять и удалять предметы, **менять время, сколько идёт пара, перемены**; изменение — **для всех пар или только для конкретной даты**.
4. Список предметов → экран предмета: **все долги**, каждая лабораторная/практическая — **отдельный блок**; по нажатию — заметка, **фото заданий или документ**.
5. К предмету можно прикреплять **документы**.
6. У предмета — **ФИО преподавателя** и **аудитория**: корпус + кабинет, запись вида «к1 28» (корпус 1, кабинет 28). Корпусов два.

## Решения оркестратора

### Модель расписания
- **Семестр:** даты начала и конца, чётность недель (через общий `calendar.week_cycle` этапа 2 или свою опорную дату — выбрать одно и описать), архив.
- **Сетка звонков** (`bell_schedule`): номер пары → начало и конец. Задаётся длительностью пары и переменами или вручную по каждой паре. Одна сетка на семестр + **изменения на дату** (другие звонки в конкретный день).
- **Пары расписания** (`class_slots`): день недели, номер пары (или своё время), предмет **или своё название** (например «Подготовка к олимпиаде»), тип (лекция, практика, лабораторная, другое), аудитория (корпус + кабинет), неделя: каждая / чётная / нечётная.
- **Особые дни** (`study_day_rules`): правило на день недели (на весь семестр) или на дату — «обычных пар нет» + свой набор занятий. Четверг заказчика = правило на четверг: обычные пары скрыты, 3 занятия «Подготовка к олимпиаде».
- **Изменения на дату** (`class_overrides`): для конкретной пары в конкретный день — отмена, перенос, другое время, другая аудитория, замена предмета. «Для всех пар» = правка самой пары или сетки звонков; «только на дату» = override.
- **Развёртка** «семестр + сетка + пары + особые дни + изменения + праздники РФ (этап 2)» → занятия на дату. Считается одинаково в Python и Dart, **общие векторы** `shared-test-vectors/study/*.json`. Занятия показываются в календаре как отдельный слой «Учёба» (не синхронизируемые события, а вычисляемые).

### Посещаемость
- Отметка на занятие: был / пропустил / **отменена** (преподавателем) / не отмечено. Отменённые и особые дни в пропуски не идут.
- Счётчик пропусков по предмету и лимит (настраивается у предмета), предупреждение при приближении к лимиту.
- «Был на паре?» — локальное уведомление после окончания занятия; не приходит в праздники, отменённые занятия и в день, где правило убрало пару.

### Предметы и долги
- **Предмет:** название, ФИО преподавателя (одно поле, текст), аудитория по умолчанию (корпус: 1 / 2, кабинет: текст), лимит пропусков, цвет не нужен (монохром), заметка, вложения (документы предмета).
- **Аудитория:** хранится как `building` (1, 2 …) + `room` (текст); показывается и вводится как «к1 28». Разбор «к1 28», «К2 101», «1-28» — общие векторы.
- **Долг** (`study_debts`): предмет, тип (лабораторная, практическая, РГР, курсовая, зачёт, экзамен, другое), номер или название («ЛР 3»), статус (не сдана, сдана, зачтена), срок, заметка, вложения (фото заданий, документы), кнопка «создать задачу» (задача этапа 2 со ссылкой на долг).
- Экран предмета: шапка (преподаватель, аудитория, пропуски/лимит), блоки долгов (каждый — отдельная карточка), документы предмета.

### Вложения — новая общая возможность (переиспользуется в других модулях)
- **Метаданные** — синхронизируемая таблица `attachments`: владелец (тип сущности + id), имя файла, MIME, размер, SHA-256, статус загрузки. **Содержимое** — отдельно от синхронизации.
- **Сервер:** `PUT /files/{attachment_id}` (загрузка, проверка размера и SHA-256, идемпотентно), `GET /files/{attachment_id}` (скачивание, только владельцу), хранение на диске VPS в отдельном томе (`FILES_DIR`); позже — S3 (интерфейс хранилища). Лимит файла 25 МБ, разрешённые типы: jpg, png, heic, webp, pdf, doc(x), xls(x), ppt(x), txt, zip. Файлы удалённых сущностей — удаляются вместе с очисткой корзины.
- **Клиент:** файл сначала сохраняется локально (офлайн работает сразу), загружается в фоне при сети; на других устройствах скачивается по требованию и кэшируется; камера и галерея для фото, выбор документа; просмотр картинок в приложении, документы — системным просмотрщиком.
- Бэкап базы в S3 (этап 1) файлы не покрывает — отметить в известных ограничениях.

### ИИ
Инструменты чтения для агента «Учёба»: расписание на период, пропуски по предметам, открытые долги.

## Объём бэкенда
Контракт `docs/specs/stage7_study.md` (таблицы, развёртка с примерами, посещаемость, долги, вложения и эндпоинты файлов, инструменты ИИ) → миграция → валидация → эталонная развёртка на Python + векторы (≥ 60: четверг-олимпиада, отмена, перенос, смена звонков для всех и на дату, чёт/нечёт, праздник, особый день на дату, разбор аудитории) → хранилище файлов → тесты.

## Объём клиента
Список предметов, экран предмета (шапка, блоки долгов, документы), карточка долга с заметкой и вложениями, редактор расписания (пары, особые дни, звонки, изменения «для всех / на дату»), расписание дня/недели учёбы, отметка посещаемости и «Был на паре?», статистика пропусков, слой «Учёба» в календаре, вложения (камера, галерея, документ, офлайн-кэш), провайдер контекста ИИ.

## Тесты (облегчённый процесс)
Высокий риск: развёртка расписания (векторы), посещаемость и счётчики, загрузка/скачивание файлов (обрыв, повтор, неверный хеш, лимит, чужой файл), офлайн-вложения. Golden — экран предмета, карточка долга, редактор расписания.
